# 손그림 본문 삽화 (Hand-drawn Article Illustrations)

## 핵심 정의

한국어 글을 위한 16:9 가로형 본문 삽화를 설계하고 생성한다. 목표는 상업 일러스트, PPT 인포그래픽, 완성형 웹툰 키비주얼이 아니다. 글 속의 핵심 판단·흐름·구조·상태·은유 하나를, 순백 배경의 얇은 사인펜 손그림 선화와 현대적인 성인 미니 캐릭터가 수행하는 1~3개의 작은 상황 컷으로 만든다.

기본 시각 IP는 `references/character-ip.md`에 정의된 캐릭터다. 캐릭터는 화면의 **핵심 동작을 직접 수행**해야 하며, 옆에 서 있는 장식이어선 안 된다.

> 캐릭터는 교체 가능하다. LabelLab 자체 캐릭터로 바꾸려면 `references/character-ip.md`만 수정하면 된다.

## 먼저 읽을 참조 파일

작업에 필요한 것만 읽고, 한 번에 컨텍스트를 다 채우지 않는다.

- `references/style-dna.md` — 스타일 DNA, 샘플 선 스타일 적용 범위, 글자, 금기.
- `references/character-ip.md` — 캐릭터의 형상·성격·동작 라이브러리·금기.
- `references/composition-patterns.md` — 구조 유형, 원본 은유 생성법, 복제 금지 규칙.
- `references/forge-routing.md` — 인스타툰 요청 규모에 따라 Forge 루프를 자동 적용할지 판단하는 기준.
- `references/prompt-template.md` — 단일 이미지 생성 프롬프트 템플릿.
- `references/qa-checklist.md` — 생성 후 검수 및 반복 규칙.

## 워크플로우

### 0. 나만의 캐릭터 지침 우선

사용자가 "나만의 캐릭터를 만들어줘", "캐릭터 지침부터 잡아줘", "내 캐릭터 스타일로 그려줘"라고 요청하면 이미지 생성보다 먼저 `references/character-ip.md`를 읽고 캐릭터 지침을 작성한다.

캐릭터 지침에는 반드시 포함한다:

- 캐릭터 이름
- 현대적인 일반 사람 기반의 외형
- 큰 머리와 작은 몸, 기억하기 쉬운 머리 실루엣
- 검은색 얇은 사인펜 선화, 손으로 빠르게 그린 듯한 흔들림
- 단순한 표정과 손동작
- 글의 핵심 행동을 직접 수행하는 역할
- 엘프, 요정, 마법사, 판타지 종족·의상·소품, 웹툰 키비주얼, 복잡한 장식 금지

사용자가 캐릭터 지침을 승인하거나 "그 스타일로 그려줘"라고 요청하면, 이후 삽화 생성 프롬프트에 해당 캐릭터 지침을 반영한다.

### 1. 본문 소화

사용자가 준 본문·링크·노션 페이지·마크다운·스크린샷을 먼저 읽는다. 다음을 추출한다:

- 핵심 주장이 무엇인가
- 어느 문단이 인지적 전환을 담당하는가
- 어디가 그림으로 설명하기 좋은가
- 어디는 글로만 충분하고 그림이 필요 없는가

균등하게 배치하지 않는다. "인지적 앵커"를 우선한다 — 핵심 판단, 두 개의 단절점, 입출력 루프, 분기, 전후 대비, 하나로 여러 용도, 이어받는 경로, 흔한 함정, 역할 상태 변화 등.

원고나 시나리오를 붙이고 "인스타툰 작성해줘"처럼 단순히 요청한 경우에도 스스로 규모를 판단한다. 2장 이상이 자연스럽거나 정보량이 큰 원고는 `references/forge-routing.md` 기준으로 Forge 루프를 자동 적용한다. 1장짜리 단편으로 충분하면 바로 생성하지 말고 단편 생성과 Forge 루프 중 어느 방식으로 진행할지 짧게 물어본다.

### 2. 먼저 삽화 전략(shot list)

사용자가 "어디에 그림을 넣을지 분석해줘 / 어디가 삽화가 필요한지 생각해줘"라고만 하면 먼저 shot list를 낸다. 각 그림마다 명시한다:

- 어느 문단 뒤에 배치
- 그림 주제
- 핵심 의미
- 구조 유형
- 캐릭터가 그림에서 무엇을 하는가
- 제안 요소
- 제안 한글 주석어

기본 4~8장. 짧은 글이면 1~3장, 긴 글도 9장을 쉽게 넘기지 않는다. 충분하면 그만 — 본문을 화보집으로 만들지 않는다.

### 3. 이미지 생성

사용자가 "생성 / 출력 / 그려줘 / 만들어줘"를 명확히 요청하면 멈춰서 확인받지 말고, **내장 `image_gen` 으로 생성**한다.

기본은 한 장이다. 다만 본문에 서로 다른 핵심 앵커가 여러 개 있거나, 한 장에 넣으면 말풍선·주석·소품이 과밀해질 때는 2~4장으로 나눠 생성한다. 긴 글이라도 쉽게 5장을 넘기지 않는다.

여러 장을 만들 때도 **한 번에 합성하지 말고, 한 장씩 따로 생성**한다. 각 이미지는 하나의 핵심 구조만 담고, 파일명은 순서대로 저장한다.

각 그림은 하나의 핵심 구조만 담는다. 프롬프트에 반드시 포함:

- 16:9 가로형 한국어 본문 삽화
- 순백 배경
- 검은색 얇은 사인펜 선화
- 채색, 명암, 그라데이션, 3D 효과 금지
- 필요한 한글 말풍선, 텍스트 오버레이, 짧은 손글씨 주석을 생성 단계에서 직접 포함
- 넉넉한 여백
- 현대적인 성인 미니 캐릭터를 핵심 동작 주체로
- PPT·상업 일러스트·판타지 캐릭터·웹툰 키비주얼·복잡한 아키텍처·좌측 상단 유형 제목 금지

과거 사례를 복제하지 않는다. 매번 현재 글에서 기이하지만 성립하는 은유를 새로 발명한다.

gpt image-gen을 사용할 때는 한글 말풍선과 텍스트 오버레이를 후처리로 분리하지 말고 프롬프트에 함께 넣는다. 문구는 정확히 렌더링할 텍스트로 따로 명시한다. 후처리 조판은 사용자가 명시적으로 원하거나, 생성 결과에서 한글이 실제로 깨진 경우에만 수정용으로 사용한다.

### 4. 검수와 반복

생성 후 `references/qa-checklist.md`로 점검한다. 캐릭터가 장식에 그치거나, 화면이 너무 빽빽하거나, 흐름도/PPT처럼 보이거나, 말풍선·텍스트 오버레이가 과밀하거나, 한글 오타가 심하거나, 좌측 상단에 원치 않는 유형 제목이 생기거나, 너무 귀엽고 뻣뻣하거나, 배경이 깨끗한 흰색이 아니면 우선 재생성 또는 부분 편집한다.

### 5. 저장·전달

사용자가 workspace 안에서 작업 중이면 `image_gen`으로 생성된 원본 파일을 보존한 뒤, 최종 이미지를 반드시 workspace의 날짜별 자산 폴더에도 복사한다. 날짜는 현재 로컬 날짜(`YYYY-MM-DD`)를 사용한다.

```text
assets/YYYY-MM-DD/
```

폴더가 없으면 자동으로 생성한다. 순서대로 이름 짓는다:

```text
01-topic-name.png
02-topic-name.png
```

같은 이름의 파일이 이미 있으면 덮어쓰지 말고 `01-topic-name-v2.png`, `01-topic-name-v3.png`처럼 뒤에 버전을 붙인다. 명시 요청 없이는 기존 자산을 덮어쓰지 않는다.

전달할 때는 생성 원본 경로와 `assets/YYYY-MM-DD/` 아래 복사본 경로를 함께 알려준다.

## 출력 톤

생성 전 전략은 짧고 정확하게. 생성 후 전달에는 포함한다: 몇 장 생성했는지, 각 그림의 용도, 저장 경로, 어느 그림이 가장 안정적이고 어느 것이 선택적인지. 스타일 이론을 길게 설명하지 말고 그림이 스스로 말하게 한다.
