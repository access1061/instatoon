# Forge 라우팅

사용자가 원고나 시나리오를 붙이고 "인스타툰 작성해줘", "인스타툰으로 만들어줘", "그려줘"처럼 단순히 요청하면 이 기준으로 자동 진행한다.

## 기본 판단

### Light 처리

다음이면 Forge 루프를 강제하지 않는다.

- 한 장의 단편 이미지로 충분하다.
- 핵심 메시지가 하나다.
- 반전, 원인, 결론이 따로 나뉘지 않는다.
- 말풍선 1~2개와 짧은 주석만으로 전달된다.
- 사용자가 "1장만", "바로", "간단히", "초안"이라고 명시했다.

이 경우 바로 생성하지 말고 한 번만 짧게 묻는다.

```text
이 원고는 1장 단편으로 충분해 보입니다. 바로 1장으로 만들까요, 아니면 Forge 루프로 shot list부터 잡을까요?
```

### Forge 루프 자동 적용

다음 중 하나라도 해당하면 확인 질문 없이 Forge 루프를 적용한다.

- 2장 이상이 자연스럽다.
- 원고 안에 문제 제기, 반전, 원인, 결론이 분리되어 있다.
- 금융, 기술, 정책, 의료, 법률처럼 오해 비용이 큰 주제다.
- 숫자, 종목명, 인과관계, 시점 정보가 많다.
- 말풍선이나 텍스트 오버레이가 한 장에 과밀해질 가능성이 높다.
- 사용자가 "3장", "5장", "캐러셀", "시리즈", "시나리오"를 언급했다.
- 이전 생성물의 QA나 수정 후보까지 관리해야 한다.

## 루프 절차

### Ask / Plan

- 핵심 주장과 감정 흐름을 찾는다.
- 권장 장수를 정한다. 기본은 3~5장이다.
- 각 장의 역할을 한 줄로 정한다.
- 각 장의 말풍선, 텍스트 오버레이, 짧은 주석을 확정한다.
- gpt image-gen에 넣을 정확한 한글 문구를 별도로 정리한다.

사용자에게 별도 확인을 요구하지 않는다. 단, 사용자가 지정한 장수와 정보량이 충돌하면 짧게 이유를 말하고 보수적으로 분리한다.

### Run

- 이미지는 한 장씩 따로 생성한다.
- 여러 장을 한 이미지에 합치지 않는다.
- 각 장은 하나의 핵심 의미만 담는다.
- 한글 말풍선과 텍스트 오버레이는 생성 프롬프트에 직접 포함한다.
- 후처리 조판은 사용자가 명시하거나 한글이 실제로 깨졌을 때만 사용한다.

### Verify

각 장마다 확인한다.

- 16:9 가로형인가.
- 스타일이 순백 배경, 검은 사인펜 선화, 최소 채색인가.
- 캐릭터가 정보 확인, 비교, 정리, 경고, 선택, 기록, 해결 중 하나를 직접 수행하는가.
- 한글 말풍선과 텍스트 오버레이가 읽히는가.
- 한 장에 정보가 과밀하지 않은가.
- 이전/다음 장과 감정 흐름이 이어지는가.
- `assets/YYYY-MM-DD/`에 저장됐는가.

### Learn

다음 작업에 반복할 만한 사실만 남긴다.

- 특정 문구가 자주 틀리면 더 짧은 문장으로 나누기.
- 한 장이 과밀하면 장수를 늘리기.
- 좋은 스타일 샘플이 생기면 다음 프롬프트의 기준으로 삼기.

### Done

마지막 보고에는 다음만 짧게 포함한다.

- 생성한 장수.
- 저장 경로.
- 가장 안정적인 장.
- 선택적으로 재생성하면 좋은 장과 이유.

## 장수 기준

- 핵심 메시지 1개: 1장 후보. 사용자에게 light/Forge 선택을 묻는다.
- 문제 제기 + 반전 + 결론: 3장.
- 원인 2개 이상 + 결론: 4장.
- 단계, 비교, 예외, 결론이 모두 필요한 긴 글: 5장.
- 6장 이상은 사용자가 명시하거나 정보가 정말 분리되어야 할 때만 사용한다.
