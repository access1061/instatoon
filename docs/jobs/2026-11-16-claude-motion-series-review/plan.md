# Claude Code 카드뉴스 → 모션그래픽: 원고 검토 및 6회 기획 초안

## 검토 상태와 범위

이번 산출물은 기획만이다. 이미지, 캡션, 발행, 독립 Visual QA는 수행하지 않는다. 다른 에이전트를 시작하지 않는다.

도구 제한: 셸은 프로세스 생성 오류로 실패했고 Node 파일 읽기도 런타임 종료로 실패했다. 따라서 로컬 AGENTS.md, docs/agent-team-workflow.md, request.md와 아래 원자료를 직접 읽었다고 주장하지 않는다. 이 초안은 요청에 전문으로 제공된 작업 지침·워크플로·선택 스킬·authoritative job data에 근거한다. 원문별 표현과 구체 사례에 대한 대조 검토는 미완료다.

원문 대조 대상: E:/Pi_workspace/naver_blog/final/blog/01_start.md, 02_install.md, 03_plan.md, 04_code.md, 05_motion.md, 06_review.md; final/review/VALIDATION.md와 REVIEW.md; source/SERIES_GUIDE.md. source는 초기안 대조에만 사용하고 final을 편집 기준으로 삼는다.

## 원고 검토 및 편집 판단

아래는 직접 원문을 검증한 결과가 아니라, 제공된 검토 사실을 기획에 반영한 판단이다.

| 쟁점 | 연재 반영 |
| --- | --- |
| 각 편 앞의 모션 설명이 입문 흐름을 끊음 | 1~4회는 기본 카드 제작, 5회는 움직임 확장, 6회는 검수와 재사용으로 재배치한다. |
| 완성 예제와 연재 규격의 혼동 | 완성 예제는 정지 5장·24초 영상. 제안하는 연재는 6회×4장=24장으로 별개다. source의 16초·3.2초 구성은 사용하지 않는다. |
| 도구 소개와 실제 완료 경로의 혼동 | HyperFrames render는 해당 환경에서 미완료. 실제 MP4 경로는 HTML/GSAP → Edge 프레임 캡처 → FFmpeg로 명시한다. 속도나 보편적 성공을 주장하지 않는다. |
| Claude의 수행 범위 과장 가능성 | 재현용 프롬프트와 로컬 실행 결과를 구분한다. 실제 제작 전부를 Claude가 수행했다는 대화 로그는 없으므로 자동 완성 성공담으로 각색하지 않는다. |
| 검수의 범위 | 청감 검수 미수행을 유지한다. 음악까지 검증 완료라고 표현하지 않는다. 실제 이미지 독립 Visual QA는 이번 기획 밖이다. |
| 검수 문서의 깨진 문장 | VALIDATION.md·REVIEW.md 모션 추가 부분의 실제 물음표로 깨진 문장은 대사나 근거 문구로 재사용하지 않는다. |
| 행사 정보의 현재성 | 일정·예약은 예제 소재로만 다룬다. 공식 최신 공지를 확인한 방문 안내로 재발행하지 않는다. |
| 설치법의 현재성 | 로컬 편집 검토로 최신 버전·설치 정확성을 인증하지 않는다. 구체 명령을 싣기 전 공식 자료 재확인이 필요하다. 이번에는 명령 전체를 싣지 않는다. |
| 예제 캐릭터와 진행 캐릭터 | 치이카와는 원자료 예제 소재다. 진행 캐릭터로 선택받았다고 간주하지 않는다. |

## 연재 방향

독자: AI로 콘텐츠를 만들고 싶지만 코드와 영상 도구가 낯선 초보 제작자.

목표: 결과와 도구 역할을 이해하고, 준비 → 사실 정리 → 카드 기획 → 레이어 수정 → 의미 있는 움직임 → 검수·재사용 순서를 따라가게 한다. 코드와 설치 명령 전체는 블로그에 남긴다.

제안 규격: 6회 연재, 회당 4장, 총 24장. 컬러 4:5. 각 장은 하나의 큰 상황으로 기획하며 상·하 2분할은 지정하지 않는다. 아래 문구는 창작 대사 초안이며 원문 인용이 아니다. 이미지 제작 시에는 확정 문구만 `Text to render exactly:` 아래에 옮긴다.

고정 역할: 은발 안내자는 절차를 안내하고, 붉은 머리 행동가는 질문과 오해·실패를 드러내며, 보라 머리 분석가는 범위와 검증을 짚는다. 원문에 없는 외형 세부와 추가 사실은 확정하지 않는다.

## 1회 — 무엇을 만들고, 도구는 무엇을 맡을까?

핵심 메시지: 결과의 종류와 도구 역할부터 구분한다.

독자 질문: 코드를 몰라도 어디서부터 이해하면 될까?

실수: Claude가 제작 전부를 자동 완료했다고 받아들이기.

실행 기준: 정지 카드와 영상, 재현용 요청과 실제 실행 결과를 구별해 말할 수 있다.

| 장 역할 | 핵심 의미 | 캐릭터 행동 | 정확한 문구 |
| --- | --- | --- | --- |
| 1-1 호기심 | 초보자의 시작 질문 | 붉은 머리가 카드와 영상 앞에서 망설인다. | 붉은 머리: “코드를 몰라도 시작할 수 있을까?” |
| 1-2 결과 구분 | 예제 규격과 연재 규격은 별개 | 은발이 예제 결과 두 묶음을 보여준다. | 은발: “예제 결과는 정지 5장과 24초 영상이야.” / 보라 머리: “우리 연재 장수와는 별개야.” |
| 1-3 도구 역할 | 요청·웹 구성·움직임의 역할 구분 | 은발이 요청서에서 카드와 움직임으로 이어지는 흐름을 가리킨다. | 은발: “Claude Code에 제작을 요청하고,” / 은발: “웹 기술로 카드와 움직임을 구성해.” |
| 1-4 범위 확인 | 프롬프트와 실행 증거 구분 | 보라 머리가 요청서와 결과물을 따로 놓는다. | 붉은 머리: “전부 자동으로 끝낸 거야?” / 보라 머리: “재현용 요청과 실제 실행 결과는 구분하자.” |

## 2회 — 설치보다 먼저, 준비 상태 확인

핵심 메시지: 준비 절차와 작동 확인을 한 묶음으로 이해한다.

독자 질문: 설치 명령만 따라 치면 준비가 끝날까?

실수: 설치 완료를 작업 가능 확인으로 간주하기.

실행 기준: 사용할 환경과 작업 위치를 정하고, 실제로 실행되는지 확인한다. 명령을 공개하기 전 최신 공식 자료를 재확인한다.

| 장 역할 | 핵심 의미 | 캐릭터 행동 | 정확한 문구 |
| --- | --- | --- | --- |
| 2-1 질문 | 준비와 설치의 차이 | 붉은 머리가 긴 명령 목록을 들고 달려온다. | 붉은 머리: “이것만 설치하면 준비 끝?” |
| 2-2 절차 | 환경과 작업 위치부터 정리 | 은발이 작업 공간을 가리키며 순서를 잡는다. | 은발: “작업할 환경과 폴더부터 정하자.” |
| 2-3 점검 | 실행 여부를 직접 확인 | 보라 머리가 실행 결과를 살피고 붉은 머리가 멈춰 확인한다. | 보라 머리: “설치했다고 바로 되는 건 아니야.” / 은발: “실제로 실행되는지 확인하자.” |
| 2-4 실행 기준 | 명령의 현재성은 별도 확인 | 보라 머리가 명령 목록에 확인 표시를 보류한다. | 보라 머리: “구체 명령은 공식 자료로 다시 확인해.” / 은발: “전체 절차는 블로그에서 이어 보자.” |

## 3회 — 카드에 넣기 전에, 사실부터

핵심 메시지: 사실의 범위를 정한 뒤 한 장의 핵심을 고른다.

독자 질문: 자료를 많이 넣으면 더 좋은 카드가 될까?

실수: 예제의 일정·예약 정보를 최신 안내처럼 옮기기.

실행 기준: 각 장의 핵심을 한 문장으로 정하고, 예제 사실과 현재 확인이 필요한 정보를 구분한다.

| 장 역할 | 핵심 의미 | 캐릭터 행동 | 정확한 문구 |
| --- | --- | --- | --- |
| 3-1 질문 | 정보 과밀의 유혹 | 붉은 머리가 자료를 카드 한 장에 쌓는다. | 붉은 머리: “자료를 전부 넣으면 되지?” |
| 3-2 사실 범위 | 자료 속 예제와 최신 정보 구분 | 보라 머리가 일정 자료 옆에 예제 표시를 놓는다. | 보라 머리: “이 일정은 자료 속 예제야.” / 보라 머리: “최신 방문 안내로 쓰면 안 돼.” |
| 3-3 기획 | 장마다 핵심 하나 | 은발이 자료를 덜어 내고 카드별 의미를 나눈다. | 은발: “한 장에서 꼭 전할 말부터 고르자.” |
| 3-4 실행 기준 | 사실과 의미를 확인하고 진행 | 붉은 머리가 한 문장만 남기고 보라 머리가 확인한다. | 붉은 머리: “이 장의 핵심은 한 문장!” / 보라 머리: “자료에 없는 사실은 더하지 말자.” |

## 4회 — 그림과 글자를 나누면 수정이 보인다

핵심 메시지: 그림·글자 레이어를 나누어 수정 대상을 명확히 한다.

독자 질문: 글자 하나가 틀렸을 때 무엇부터 고쳐야 할까?

실수: 수정 범위를 정하지 않고 카드 전체를 다시 만들기.

실행 기준: 그림과 글자의 수정 대상을 나누고, 수정 후 문구와 배치를 다시 확인한다.

| 장 역할 | 핵심 의미 | 캐릭터 행동 | 정확한 문구 |
| --- | --- | --- | --- |
| 4-1 문제 | 작은 오류 앞의 과한 수정 | 붉은 머리가 틀린 글자를 보고 카드 전체를 바꾸려 한다. | 붉은 머리: “글자 하나 틀렸는데, 전부 다시?” |
| 4-2 구조 | 그림과 글자의 역할 분리 | 은발이 그림 층과 글자 층을 나누어 보여준다. | 은발: “그림과 글자 레이어를 나눠 보자.” |
| 4-3 수정 | 바꿀 부분을 구체적으로 지정 | 보라 머리가 글자 영역만 짚는다. | 보라 머리: “무엇을 고칠지 먼저 정해.” / 붉은 머리: “이번엔 글자부터!” |
| 4-4 확인 | 수정 결과를 다시 읽기 | 세 사람이 수정된 카드의 문구와 위치를 살핀다. | 은발: “고친 뒤에는 다시 읽어 보자.” / 보라 머리: “문구와 배치도 함께 확인해.” |

## 5회 — 움직임은 정보를 돕는 만큼

핵심 메시지: 정지 카드가 정리된 뒤 정보 전달을 위한 움직임으로 확장한다.

독자 질문: 많이 움직이면 더 잘 전달될까?

실수: 화려함이나 특정 도구의 렌더 성공을 먼저 약속하기.

실행 기준: 움직임이 읽는 순서를 돕는지 확인하고, 실제 MP4 완료 경로와 미완료 경로를 구분한다.

| 장 역할 | 핵심 의미 | 캐릭터 행동 | 정확한 문구 |
| --- | --- | --- | --- |
| 5-1 질문 | 움직임의 목적 묻기 | 붉은 머리가 카드 요소를 모두 움직이려 한다. | 붉은 머리: “전부 움직이면 더 잘 보일까?” |
| 5-2 전환 | 기본 제작 후 모션 확장 | 은발이 정리된 카드에서 필요한 요소만 차례로 짚는다. | 은발: “카드를 먼저 정리하고,” / 은발: “읽는 순서를 돕는 움직임을 붙이자.” |
| 5-3 실제 경로 | 완료된 MP4 경로 명시 | 보라 머리가 세 단계 경로를 가리킨다. | 보라 머리: “실제 MP4는 이 경로로 만들었어.” / 도식: “HTML/GSAP → Edge 프레임 캡처 → FFmpeg” |
| 5-4 한계 | 환경별 결과를 일반화하지 않기 | 보라 머리가 미완료 표식을 보이고 붉은 머리가 결과를 확인한다. | 보라 머리: “HyperFrames render는 이 환경에서 미완료야.” / 은발: “빠르다거나 늘 성공한다고 말할 수는 없어.” |

## 6회 — 완성 선언 전에, 확인한 범위부터

핵심 메시지: 오류와 미확인 항목을 기록하고 재사용할 때 다시 확인한다.

독자 질문: 파일이 나왔으면 검수도 끝난 걸까?

실수: 일부 확인을 전체 검증 완료로 확대하기.

실행 기준: 확인한 것과 미확인 사항을 나누어 기록하고, 다음 작업에서 사실·문구·결과를 다시 검토한다.

| 장 역할 | 핵심 의미 | 캐릭터 행동 | 정확한 문구 |
| --- | --- | --- | --- |
| 6-1 질문 | 출력과 검수는 다른 단계 | 붉은 머리가 결과 파일을 들고 완료를 외치려 한다. | 붉은 머리: “파일 나왔으니 검수도 끝?” |
| 6-2 오류 확인 | 문구와 결과를 다시 검토 | 은발이 결과를 펼치고 보라 머리가 오류 항목을 짚는다. | 은발: “문구와 결과를 다시 확인하자.” / 보라 머리: “깨진 문장은 근거로 옮기지 말고.” |
| 6-3 미확인 범위 | 청감 검수 미수행 유지 | 보라 머리가 음악 확인 칸을 비워 둔다. | 보라 머리: “청감 검수는 수행하지 않았어.” / 붉은 머리: “음악까지 확인 완료라고 쓰면 안 되겠네.” |
| 6-4 재사용 | 구조를 활용해도 재검토 필요 | 은발이 다음 작업용 빈 카드를 놓고 세 사람이 확인 기록을 챙긴다. | 은발: “구조는 다음 작업에도 활용하자.” / 보라 머리: “사실과 결과는 다시 확인하고.” |

## 다음 단계 전 원문 대조 항목

1. 여섯 블로그 원문을 직접 읽고 회차별 근거와 표현을 대조한다. 특히 준비 점검과 레이어 분리의 구체 범위를 확인한다.
