# 2화: 원하는 배치를 구체적으로 요청하기

## QA 첨부 역할과 총괄 크기 검사
4장 수정본은 qa-04-v2로 재검수한다. 원래 4장 대사와 글자를 유지하고 시사가 열린 파일 화면을 확인하며 하치와레가 하단 layout-notes.md에 기록을 준비하는 행동으로 편집한다. 임의 CSS 값이나 새 문구를 화면에 넣지 않는다. 노트에 추상 선만 있는 것은 기록 완료를 뜻하지 않는다. 최종 확정 파일은 04-review-and-record-v2.png 예정이며 이전 파일은 수정 기록이다.
3장 예제 안의 식별용 ‘3 운영시간’ 표기를 허용한다. 이는 요청문의 카드 번호와 증상을 연결하는 원문 근거 라벨이다. 상단 돋보기 속에서는 오른쪽 경계로 ‘운영시간’ 끝이 일부 잘려 보이는 것이 의도된 오류 예시이고, 본문 요청문과 하단 정상 라벨은 전부 읽혀야 한다. 3장 주연은 하치와레·시사, 컷 경계로 재등장한다.
2장 생성본에는 실제 크기 도식의 가로 ‘1080px’ 세로 ‘1350px’ 보조 라벨을 허용한다. 원문과 일치하는 시각 설명이다. 작게 재현한 카드 내부 캐릭터는 예제 카드의 도상이며 실제 출연 중복으로 간주하지 않는다. 2~4장 QA의 첫 첨부는 각 최종 검수 대상, 두 번째는 첫 장 PASS 앵커, 세 번째는 원본 캐릭터 참고. 모든 최종본은 총괄이 fit_instagram_4x5.py로 1080×1350 저장 성공을 확인한 뒤 첨부한다.
qa-01-v1의 첫 첨부는 assets/2026-11-16/ai-motion-ep02/layout/01-be-specific.png 검수 대상 최종본. 나머지는 원본 캐릭터/1화 스타일 참고다. 총괄이 보정기로 1080×1350 저장 성공을 확인했다. QA는 첫 첨부를 실제 열어 시각 검수하고 파일 읽기 오류와 이미지 열람 실패를 구분해 보고한다. 첫 장의 카드 세 번째 위치는 장면상 생략해도 번호와 문제 위치를 묻는 의미가 전달되면 허용한다. 생성된 이미지 자체를 검수하며 총괄의 크기 확인을 독립 측정으로 주장하지 않는다.

최신 사용자 요청: 기존 02_install.html 내용 취소. E:/Pi_workspace/naver_blog/final/blog/03_plan.html 내용으로 2회차 이미지를 생성한다. 총괄이 원문 HTML을 실제 읽었다. 이전 job과 첫 장은 폐기된 시안으로 보존하며 이번 결과에 포함하지 않는다.

출력: assets/2026-11-16/ai-motion-ep02/layout/ (기존 파일 보존). 스킬 handdrawn-illustrations3, 4장, 4:5 1080×1350, 치이카와·하치와레·시사. 원본 참고 refer/1116/chikawa.jpg 와 chikawa2.jpg. 1화 스타일 앵커 assets/2026-11-16/ai-motion-ep01/01-course-question-v3.png. 작고 둥근 몸, 크림 카디건/민트 후드/시사 복숭아 카디건·둥근 안경·메모장, 파스텔 수채 질감·진갈색 선. 원본을 실제 이미지 입력으로 전달한다. 새 첫장 PASS 후 후속 장 앵커로 사용. 판타지 캐릭터로 바꾸지 않는다.

원문 핵심: 3번 카드처럼 문구가 긴 카드를 기준으로 넘침·겹침 관찰. 미리보기 축소 비율이 아닌 실제 1080×1350 카드 픽셀로 요청. theme.css 배치만 수정하고 cards.js/문구/그림 유지. 원문의 예시 h1 76px, 설명 27px, 제목 줄높이 1.15. 문제가 실제 보일 때만 카드 번호+증상 전달, 문구를 삭제·요약하지 않고 필요한 CSS만 수정. 같은 CSS가 1~5 전부에 영향하므로 다른 카드도 확인. 제목 두 줄/운영시간 끝/그림 잘림/얼굴 가림/버튼 작동을 점검. 적용된 실제 theme.css 값을 읽어 layout-notes.md 기록, 추측하지 않기.

4장 기획과 정확한 문구를 다음대로 다듬되 핵심 유지:
1 제목 ‘예쁘게 말고, 구체적으로!’ / 치이카와 ‘글자가 잘렸어…’ / 하치와레 ‘몇 번 카드, 어느 부분이야?’ / 시사 ‘긴 문구가 있는 카드부터 보자.’ 3번 연습 카드에서 넘침을 발견한 장면. 오류를 실제 앱 캡처로 사칭하지 않는 그림, 표기 ‘연습 예제’.
2 제목 ‘어디를, 얼마나 바꿀까?’ / 하치와레 ‘문구와 그림은 그대로!’ / 큰 요청 메모 ‘실제 카드 1080×1350px’ ‘제목 76px · 설명 27px’ ‘배치만 수정해줘’ / 시사 ‘숫자는 미리보기 크기가 아니야.’ 수치는 이 예제의 요청값이며 보편적 정답 아님.
3 제목 ‘문제가 보인 부분만!’ / 요청 카드 ‘3번 운영시간이 오른쪽에서 잘려.’ ‘문구는 유지하고 배치만 고쳐줘.’ / 시사 ‘원인부터 확인하자.’ / 하치와레 ‘다른 카드 영향도 알려줘.’ 증상-국소 수정 원리. 상하 2컷 가능. 문구를 지우는 장면 금지.
4 제목 ‘다시 보고, 기준을 남겨요’ / 점검 메모 ‘제목 · 긴 문구 · 그림 · 버튼’ / 치이카와 ‘다른 카드도 확인!’ / 하치와레 ‘실제 적용값을 기록해줘.’ / 노트 이름 ‘layout-notes.md’ / 시사 ‘추측 말고 파일에서 확인!’ 다섯 카드 재확인 후 실제 값을 기록하는 행동. 실행 성공 인증이나 실제 화면처럼 그리지 않는다.

문구 추가 금지, 한 장 2~3명, 제목·말풍선 가독성. 각 장은 장 역할/핵심 의미/행동/정확한 문구로 plan.md 작성. 다른 작업자 변경 되돌리기/재위임 금지. 이미지 제작은 총괄, QA는 첨부를 실제 열어 검수. 최종 캡션은 100~500자, 그림 대사 반복 대신 원문 보충: theme.css 변경 영향, 관찰 증상, 실제 적용값 기록. 최신 요금·추천·설치법 없음. 외부 발행 없음.
