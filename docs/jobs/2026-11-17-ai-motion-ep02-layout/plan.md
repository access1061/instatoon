# 2화: 원하는 배치를 구체적으로 요청하기

총괄 편집 보완: 1장은 아직 카드 번호를 묻는 단계이므로 카드 1장과 오른쪽 넘침으로 충분하다. 세 번째 위치를 별도로 시각화하는 설명은 필수 조건에서 제외한다. 실제 카드 번호+증상의 정확한 요청은 3장에서 제시한다. 문구·의상·참고·주제는 유지한다. QA 최종본 경로와 크기 검사 결과는 request.md 상단 기준.

## 1장
- **장 역할:** 문제 발견 — 예쁜 배치라는 막연한 요구를 구체적인 관찰로 전환한다.
- **핵심 의미:** 문구가 긴 3번 연습 카드에서 넘침·겹침을 먼저 살피고, 카드 번호와 문제 위치를 확인한다.
- **캐릭터 행동:** 크림 카디건의 치이카와가 3번 연습 카드의 잘린 글자 끝을 가리키며 당황한다. 민트 후드의 하치와레가 같은 위치를 들여다보고, 복숭아 카디건·둥근 안경의 시사가 메모장을 들고 긴 문구를 짚는다. 카드 번호는 세 번째 위치를 손으로 가리켜 전달하고 별도 숫자 라벨은 추가하지 않는다. 카드 그림 옆에 ‘연습 예제’를 명확히 표시한다. 실제 앱 캡처처럼 그리지 않는다. 세 캐릭터의 작고 둥근 몸과 고유 얼굴·귀·색·실루엣을 유지하고 파스텔 수채 질감·진갈색 선을 적용한다. 원본 참고 `refer/1116/chikawa.jpg`, `refer/1116/chikawa2.jpg`와 1화 앵커 `assets/2026-11-16/ai-motion-ep01/01-course-question-v3.png`를 제작 시 실제 이미지 입력으로 전달한다. 4:5, 최종 1080×1350으로 구성한다.
- **정확한 문구 — Text to render exactly:**
  - 제목: 예쁘게 말고, 구체적으로!
  - 치이카와: 글자가 잘렸어…
  - 하치와레: 몇 번 카드, 어느 부분이야?
  - 시사: 긴 문구가 있는 카드부터 보자.
  - 예제 표기: 연습 예제

## 2장
- **장 역할:** 요청 기준 구체화 — 수정 범위와 수치를 정한다.
- **핵심 의미:** 미리보기 축소 비율 대신 실제 카드 1080×1350 픽셀을 기준으로 요청한다. 제목 76px·설명 27px은 이 예제의 요청값이며 보편적인 정답으로 제시하지 않는다. `theme.css` 배치만 수정하고 `cards.js`·문구·그림은 유지한다.
- **캐릭터 행동:** 하치와레가 큰 요청 메모를 펼치고 문구와 그림을 그대로 두자는 손짓을 한다. 시사는 메모의 실제 카드 크기와 수치를 차례로 짚는다. 두 캐릭터만 배치해 메모와 말풍선의 가독성을 확보한다. 수치는 요청 메모 안에만 두고 권장 기준표나 적용 완료 결과로 표현하지 않는다. 첫 장과 같은 의상·비율·수채 질감·진갈색 선을 유지하며, 새 첫 장이 QA PASS를 받으면 그 실제 이미지를 후속 장 스타일 앵커로 전달한다. 각 장은 별도 4:5 이미지로 제작한다.
- **정확한 문구 — Text to render exactly:**
  - 제목: 어디를, 얼마나 바꿀까?
  - 하치와레: 문구와 그림은 그대로!
  - 큰 요청 메모 첫 줄: 실제 카드 1080×1350px
  - 큰 요청 메모 둘째 줄: 제목 76px · 설명 27px
  - 큰 요청 메모 셋째 줄: 배치만 수정해줘
  - 시사: 숫자는 미리보기 크기가 아니야.

## 3장
- **장 역할:** 관찰한 증상 전달 — 원인을 확인하고 필요한 배치만 수정하도록 요청한다.
- **핵심 의미:** 문제가 실제로 보일 때 카드 번호와 증상을 전달한다. 문구를 삭제·요약하지 않고 필요한 CSS만 수정하며, 공통 CSS가 다른 카드에 미치는 영향도 확인한다.
- **캐릭터 행동:** 하나의 4:5 이미지 안을 상·하 두 상황 컷으로 나눈다. 상단에서 하치와레가 두 줄 요청 카드를 펼쳐 보여준다. 하단에서 시사가 메모장을 들고 문제 위치와 배치를 살피고, 하치와레는 나머지 카드들을 가리키며 영향 확인을 요청한다. 출연자는 두 명이며 같은 의상과 작은 체형을 유지한다. 글자 삭제·요약·지우개 동작이나 해결 완료 표시를 그리지 않는다. 요청 카드에 문제 문구를 별도로 만들어 넣지 않고 지정된 두 문장만 쓴다.
- **정확한 문구 — Text to render exactly:**
  - 제목: 문제가 보인 부분만!
  - 요청 카드 첫 줄: 3번 운영시간이 오른쪽에서 잘려.
  - 요청 카드 둘째 줄: 문구는 유지하고 배치만 고쳐줘.
  - 시사: 원인부터 확인하자.
  - 하치와레: 다른 카드 영향도 알려줘.

## 4장
- **장 역할:** 전체 재확인과 기록 — 배치를 다시 보고 실제 적용값을 남긴다.
- **핵심 의미:** 같은 CSS의 영향을 받는 다섯 카드를 모두 확인한다. 제목 두 줄, 운영시간 끝, 그림 잘림, 얼굴 가림, 버튼 작동을 점검하고 실제 `theme.css` 값을 읽어 `layout-notes.md`에 기록한다. 값을 추측하거나 요청값을 적용값으로 간주하지 않는다.
- **캐릭터 행동:** 치이카와가 다섯 장의 작은 카드 그림을 차례로 살핀다. 하치와레는 점검 메모 옆에서 기록할 노트를 펼치고, 시사는 열린 파일과 노트를 번갈아 가리킨다. 세 캐릭터가 실제 값을 확인한 뒤 기록하려는 과정으로 표현한다. 노트에는 지정된 파일명만 표시하고 확인하지 않은 CSS 값이나 코드, 실행 성공 배지, 모두 통과한 체크 표시를 추가하지 않는다. 실제 화면을 재현한 인증 이미지처럼 그리지 않는다. 제목·말풍선·점검 메모가 서로 겹치지 않게 배치한다.
- **정확한 문구 — Text to render exactly:**
  - 제목: 다시 보고, 기준을 남겨요
  - 점검 메모: 제목 · 긴 문구 · 그림 · 버튼
  - 치이카와: 다른 카드도 확인!
  - 하치와레: 실제 적용값을 기록해줘.
  - 노트 이름: layout-notes.md
  - 시사: 추측 말고 파일에서 확인!
